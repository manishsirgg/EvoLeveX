# PR #290 — Staging issuer/worker authorization transaction test

This disposable PostgreSQL 15/17 integration test connects **two authenticated database LOGIN principals** (issuer and worker) to a restricted test-only SECURITY DEFINER issuance/consumption protocol. Neither principal may read the ticket table or invoke the other's entry point. Issuance requires an eligible operator and a reconciliation-required attempt, stores a SHA-256 digest of a 256-bit ticket, and imposes a database-clock 30-second expiry. Consumption locks and checks the ticket, operator and attempt, then commits ticket use, a unique nonce and a correlation record together. Tests reject replay, cross-principal execution, direct table access and issuance following revocation.

**Not production-ready:** the operators, attempts, nonce and correlation tables in this integration test are **synthetic**, not the actual Store schema. Issuer credential possession is the test trust root; it does not prove a genuine Supabase-authenticated administrator requested issuance. This test does not use the real owner-only `private.execute_evo_store_correlation_atomically` function, nor independently verify Razorpay GET evidence. The independent real-schema owner-only checks in prior PRs remain separate. The next integration must bind authenticated issuer requests to actual Store role and attempt rows, enforce nonce/ticket/real correlation together, and include an issuer compromise threat model before any SQL grants are considered.

No production migration, roles, credentials, worker connection, SQL grants, payment initiation/capture or Printful fulfillment. The deny-all production proof gate remains unchanged.
